## 目标
把项目里的诊断性 `print` 改成 `logging` 日志打印，集中配置 + 环境变量控制级别；交互式 CLI 的 UI 输出（banner、提示、工具调用展示、✓ 成功提示等）保留 `print`。

## 1. 集中日志配置 — `src/office_agent/config.py`
- 顶部 `import logging`
- 新增 `setup_logging() -> None`：
  - 从现有 `env()` 同样的优先级读 `LOG_LEVEL`（环境变量 > pyproject > 默认 `"INFO"`）
  - `logging.basicConfig(level=..., format="%(asctime)s [%(levelname)s] %(name)s: %(message)s", datefmt="%H:%M:%S")`
  - `setup_logging()` 在模块顶部 `_load()` 之后**自动调用一次**（保证任何 `import office_agent.*` 就已配好日志）
- `_load()` 增加 `log_level: str` 字段到 `Settings` dataclass，供其他地方读取
- `pyproject.toml` 的 `[tool.office-agent]` 段增加 `LOG_LEVEL = "INFO"` 默认值

## 2. `scripts/fetch_officecli.py` —— 全部转 log（这是诊断脚本）
- `import logging` + `logger = logging.getLogger("fetch_officecli")`
- `main()` 入口先调 `logging.basicConfig(...)`（此脚本独立运行，不 import office_agent.config，需自配）
- 转换映射：
  - `print(f"[检测] ...")` → `logger.info(...)`
  - `print(f"[下载] ...")` / `"完成 ... MB"` → `logger.info(...)`
  - `print(f"[版本] ...")` → `logger.info(...)`
  - `print(f"[完成] ...")` 及其后续两行 → `logger.info(...)`
  - `print("[校验] SHA256 通过")` / `"release 未提供..."` / `"未找到对应条目..."` → `logger.info(...)`
  - `print(f"[校验] 失败: ...")` → `logger.warning(...)`
  - `print(f"[校验] 跳过（{e}）")` → `logger.warning(...)`
  - `print(f"[错误] ...")` → `logger.error(...)`
  - `print("[提示] ...")`（代理设置多行）→ `logger.info(...)` 用 `\n` 拼接
- **保留**：进度条 `sys.stdout.write("\r       [bar]...")` —— 日志无法表达进度条；末尾的 `print()` 换行也保留为 `sys.stdout.write("\n")`
- `raise SystemExit(...)` 保留不变（这是退出信号，不是日志）

## 3. `main.py` —— 仅诊断输出改 log，UI 保留 print
- `import logging` + `logger = logging.getLogger("office_agent.main")`
- `from office_agent.config import ... setup_logging` 不需要（config 已自配）
- **改 logger**：
  - `_check_officecli`: `print(f"{_DIM}[ok] officecli: ...")` → `logger.info("officecli: %s", bin_path)`；错误分支的 `print(f"{_RED}[error] {e}")` → `logger.error("officecli 解析失败: %s", e)`（但保留 `_YELLOW` 提示"请先运行 fetch"为 print，因为它是给终端用户看的行为指引）
  - `run()` 的 `except Exception` 分支：`traceback.print_exc()` → `logger.exception("agent 运行异常")`（删掉 `import traceback`）；`print(f"{_RED}运行出错: {e}")` → `logger.error("运行出错: %s", e)`
  - `except KeyboardInterrupt` 的"已中断"保留 print（用户操作反馈）
- **保留 print**（UI）：`_banner`、`_read_requirement` 的提示与"需求:"回显、`_ask_doc_kind`、`_print_agent_step`（思考/工具调用展示）、`_print_tool_results`、`_handle_interrupt`/`_collect_form`/`_collect_single_question` 的所有问答卡片 UI、"输出文件:"、"开始生成…"、最终结果 banner（✓ 文档已生成/未能生成等）、GraphRecursionError 的用户提示
- `run()` 末尾的 `print(f"{_RED}未能生成文档...")` 保留（最终结果给用户看）

## 4. 模块文件 —— 加 logger 记录异常/调用细节
这些文件目前没有 print，但应通过 logger 把诊断信息留下（供 DEBUG 排查）：

- **`src/office_agent/officecli.py`**：`logger = logging.getLogger(__name__)`
  - `_Runner.run` 失败时（`FileNotFoundError`/`TimeoutExpired`/非零 returncode）`logger.debug("officecli 命令失败: %s, stderr=%s", cmd, stderr)` —— 不影响原有 raise
  - 成功执行时 `logger.debug("officecli cmd: %s", args[:3])` 便于排查

- **`src/office_agent/tools.py`**：`logger = logging.getLogger(__name__)`
  - `_wrong_kind_msg` 调用前 `logger.warning("工具与文档类型不匹配: %s", ...)`（可选）

- **`src/office_agent/graph.py`**：`logger = logging.getLogger(__name__)`
  - `_tools_node` 的异常分支：`logger.exception("工具 %s 执行失败", name)` —— 原代码把异常吞成字符串返回给 LLM，加 logger 后诊断信息留存
  - 软收尾提醒触发时 `logger.debug("触发软收尾提醒: used=%d", used)`

## 5. 配置文档
- `.env.example` 增加注释段：
  ```
  # ===== 日志 =====
  # 日志级别: DEBUG/INFO/WARNING/ERROR（默认 INFO）
  LOG_LEVEL=INFO
  ```
- `pyproject.toml` 的 `[tool.office-agent]` 段补 `LOG_LEVEL = "INFO"`

## 验证
- `python main.py "测试"` —— 确认 banner/提示/工具展示仍是彩色 print；错误时 `[error]` 变成 logger.error 输出
- `LOG_LEVEL=DEBUG python main.py "测试"` —— 确认能看到 officecli 命令的 debug 日志
- `python scripts/fetch_officecli.py`（或断网模拟）—— 确认 `[下载]/[错误]` 变成带时间戳的 logger 输出，进度条仍是 `\r` 刷新
- `python -c "from office_agent.config import settings; print(settings.log_level)"` —— 确认配置读取正常

## 不改的东西
- 任何 `raise SystemExit(...)`（退出信号）
- `input(...)` 提示（logger 不能驱动输入）
- 进度条 `sys.stdout.write("\r...")`
- `assert_llm_ready` 内的 `raise SystemExit`（已是规范错误退出）
